# 基金 / 指数详情页加「PE + 危险值 / 中位值 / 机会值 / 分位点」可行性分析

> 调研日期 **2026-10-22**（所有数字都是当天实测快照）。**只做分析，不动代码。**
> 结论先行：**指数页可行且值得做（范围要收窄）；基金页的「PE 五件套」不建议做。**

---

## 0. TL;DR

| 问题 | 结论 |
|---|---|
| 技术上能做吗 | 能。蛋卷（danjuan）公开接口一次请求给 63 个指数的 PE/PB/分位，10 年周频历史可自算三档带值；单次 0.3s，无需 key |
| 现有链路够用吗 | 不够。`IndexDetailDto` 没有任何估值字段；东财 push2 对指数**不返回 PE/PB 字段**（实测） |
| 「分位点」能直接拿吗 | 能拿，但**必须自己选窗口**。同一天沪深300：10 年窗口分位 50%、全历史（2005 起）分位 41%；等权口径下只有 19% |
| 「危险/中位/机会值」是什么 | 不是数据源字段，而是**历史 PE 的 80%/50%/20% 分位值**（韭菜说/螺丝钉系口径）。可自算，但窗口与分位点必须同一套 |
| 指数页要不要做 | **建议做**（P1，一个卡片，覆盖 A 股 63 只里的主流宽基+行业） |
| 基金页要不要做 | **不建议**做 PE 五件套：只有 13%（30 只随机样本）的指数基金能映射到有估值数据的指数，主动基金聚合 PE 覆盖只有前十大重仓（≈50–70%），语义错位且会误导 |
| 主要风险 | 口径（加权/等权差 1–2 倍）、窗口（差 9pp）、第三方未公开 API 无 SLA、把「危险值」读成卖出信号的误导 |

工作量估算：**指数页 1.5–2 人日**（service ~250 行 + 前端 ~200 行 + 测试 + 文档），基金页若强行做再加 1–1.5 人日且效果差。

## 1. 需求拆解：五个字段到底是什么

| 字段 | 真实含义 | 能否直接取 | 备注 |
|---|---|---|---|
| PE | 指数成分股加权市盈率（TTM/静态） | ✅ 多源可直取 | 口径差异巨大，见 §4 |
| 分位点 | 当前 PE 在**某个窗口**历史中的排名百分位 | ⚠️ 源给的值窗口不同 | 必须把窗口写进 UI |
| 机会值 | 历史 PE 的 20% 分位值（低估值区上沿） | ❌ 需自算 | 本质是分位数，不是独立指标 |
| 中位值 | 历史 PE 的 50% 分位值 | ❌ 需自算 | 同上 |
| 危险值 | 历史 PE 的 80% 分位值（高估值区下沿） | ❌ 需自算 | 同上 |

⚠️ 三个「值」与「分位点」是同一份历史序列的两种表述（值 ↔ 分位）。**只要历史序列选定，「四件」就同时确定**；反过来，如果混用两个源（比如 PE 用 A 家、分位用 B 家），四个数字会互相矛盾。

- `frontend/src/components/FundDetail.vue`：网格卡片（净值曲线/排名/资产/持有人/规模/申购赎回/持仓/经理/能力/同类），`FundBasicInfo.vue` 顶部已有 `sharpe_ratio_1y / max_drawdown_1y / volatility_1y` 与行业标签。
- `service/src/types/fund.ts` `FundDetailDto`：16 个 section，**无 benchmark / 跟踪标的**（但 `fundmobapi` 原始响应里有，见 §5）。
- 项目里已有的定期数据源大部分在 `service/src/providers/`，`packages/core` 只做纯计算（分位计算适合放这里，前端/服务端同源）。

**实测**：东财 push2 对指数没有 PE 字段 ——
`push2.eastmoney.com/api/qt/stock/get?secid=1.000300&fields=...f9,f23...` 返回里**根本不带 f9/f23**（个股 `ulist.np` 的 f9=18.51 茅台 / f23=6.56 正常）。所以「PE 从东财行情顺手取」这条路不通。

## 4. 最要命的发现：口径差 1–2 倍

同一天（2026-10-22）、同一指数、不同源/不同口径的 PE：

| 指数 | 蛋卷 PE | 乐咕 加权滚动 | 乐咕 等权滚动 | 中证官方 市盈率1 |
|---|---|---|---|---|
| 沪深300 | 12.73 | 12.06 | **28.62** | 13.76 |
| 上证50 | 10.72 | 10.68 | 28.05 | 11.90 |
| 中证500 | 28.70 | 23.41 | 40.34 | 25.77 |
| 中证1000 | 37.53 | 25.70 | 53.62 | 29.46 |
| 创业板指 | 29.75 | 25.63 | 58.63 | —（中证无 399 系） |
| 科创50 | 106.02 | 64.22 | 72.25 | 85.68 |

- **加权 vs 等权**：沪深300 是 12.06 vs 28.62（差 137%）。分位也随之从 41% 变成 19%。
- **加权 vs 加权仍然不一致**：中证1000 25.70 vs 37.53（差 46%），科创50 64.22 vs 106.02（差 65%）——大概率是「是否剔除亏损/负 PE 成分股」的处理差异。
- **窗口**：同一口径（加权滚动）沪深300 的分位，全历史（2005 起）**41%**，10 年 **50%** —— 差 9pp；而在「等权 + 全历史」口径下是 **19%**。

👉 产品含义：**四个数字只要有一个来源/口径没写在界面上，用户就没法判断它是「低估」还是「故障」**。这不是可以靠「多接几个源取平均」解决的问题（取平均会产生一个哪家都不是的数字）。

## 5. 基金侧还算不算得出来

### 5.1 基金 → 指数映射：可靠（比预想好）

`fundmobapi.eastmoney.com/FundMNewApi/FundMNBasicInformation`（**UA 必须是 okhttp/4.9.0**，与重仓股那条坑同源）响应里直接有：

```
110020 → INDEXCODE 000300, INDEXTEXCH 1, INDEXNAME 沪深300指数
159915 → INDEXCODE 399006, INDEXTEXCH 2, INDEXNAME 创业板指数(价格)
588000 → INDEXCODE 000688, INDEXTEXCH 1, INDEXNAME 上证科创板50成份指数
005827 → INDEXCODE --,     INDEXTEXCH --, INDEXNAME --（主动基金，无）
```

`INDEXTEXCH` 1→SH / 2→SZ 即可拼出蛋卷代码（`SH000300` / `SZ399006`）。QDII 要别名（蛋卷 `NDX` vs 东财 `NDX100`）。

### 5.2 但**覆盖率只有 13%**

从本地筛选库（`service/data/gofund.db`，`screening_funds` 3334 只）里随机抽 30 只「指数型/ETF」基金：

- 有 `INDEXCODE`：30/30
- 该指数在蛋卷有估值：**4/30 = 13%**（命中：中证500、中证煤炭、上证红利、中证银行）
- 落空的是：科创100、科创200、通信设备、人工智能、5G通信、创业板人工智能、半导体芯片、纳斯达克100(别名)、中债政策性金融债……

另一条「按基金名匹配指数名」的野路子：500 只里能匹配 116 只（23%），但**假阳性严重**（「华夏创业板人工智能ETF」被匹配成「创业板」——指数与实际跟踪标的完全不同）。

### 5.3 主动基金聚合 PE：技术上可做，语义上不该做

- 东财 `push2 ulist.np` 的 `f9`（PE）/`f23`（PB）个股可用（茅台 18.51/6.56）。
- 但 `holdings` 只有**前十大重仓**（占净值 ≈50–70%，季报口径、滞后 1–3 个月）。
- 「基金 PE」= 前十大加权 PE，**剩下 30–50% 不知道**；且没有历史持仓，**无法算分位**。
- 主动基金的估值高低本来就不该由「组合 PE」表达（风格、久期、行业结构都不一样）。

## 6. 是否真的需要？（分场景判断）

### 6.1 指数详情页：需要，但价值是「有比没有好」，不是核心功能

支持做的理由：

1. 用户的决策场景明确存在：这个 App 有定投回测、4433 筛选、告警、组合再平衡 —— 用户是在**做择时/配置决策**的，估值分位是这个决策链上唯一缺失的一环。
2. 成本低：一个 HTTP（0.3s）+ 一个卡片，不动现有链路，失败可降级。
3. 有复用价值：pi 工具 `get_index_valuation` 一行参数就能让终端分析用上（当前 pi 工具面 59 个，缺这一类）。

反对/克制的理由：

1. **「危险值 / 机会值」是营销化命名**。同一份数据换窗口就能让「机会」变「危险」，把它当成买卖信号会害人。要么改名「历史 20/80 分位 PE」，要么在卡片上把窗口+口径写死并加免责声明。
2. **指数详情页的使用频次没有埋点**，无法证明它被常看。先做最小版本（一个卡片），不要一上来做交互式估值历史图。
3. 回测引擎里已有「均线偏离」这类择时策略，估值分位与它有部分功能重叠（可作为后续策略模板的输入，但不是现在）。

### 6.2 基金详情页：不建议做 PE 五件套

- 只有 13% 的指数基金能拿到跟踪指数的估值；主动基金的「组合 PE」既不准也没有历史。
- 真实需求可以被更便宜、更诚实的指标满足，而且**数据已经在库里**：
  - `ranking_percentage`（同类排名分位，已在 `FundRankingTrend` 展示）；
  - `nav_history` 已有 31.9 万条（10 年），可算「当前回撤分位 / 净值分位」；
  - 若要讲估值，就讲**它跟踪的那只指数**，并在标题写明「跟踪指数：沪深300」，而不是假装这是基金的属性。

**如果用户坚持要基金页也有一块**：只对能映射到的指数基金显示，标题写「跟踪指数估值（沪深300）」+ 一行「本基金为指数基金，估值取自其跟踪指数」，其余类型整块隐藏。别做「基金 PE」。

## 7. 若做：建议方案（指数页 P1）

**范围**：`/market/index/:code/detail` 的同级新增 `GET /api/market/index/:code/valuation`；只对蛋卷 63 只里有的 A 股/海外指数返回 `available`，其余 `unavailable`（沿用 breadth / north_flow 的 `data_status` 约定，0 就是占位不是数据）。

**DTO**

```ts
interface IndexValuationDto {
  index_code: string;          // SH000300
  index_name: string;          // 沪深300
  as_of: string;               // 2026-10-21（历史末点）/ 2026-10-22（快照）
  source: 'danjuan';
  data_status: 'available' | 'unavailable';
  pe: number | null;
  pb: number | null;
  dividend_yield: number | null; // yeild
  roe: number | null;
  percentile: { pe: number | null; pb: number | null };     // 0.498
  window: { start: string; end: string; points: number; freq: 'weekly' };
  bands: { opportunity: number | null; median: number | null; danger: number | null }; // 20/50/80 分位 PE
  series?: Array<{ date: string; pe: number }>;             // 可选，供小图
}
```

**口径写死并显示**：「加权 · 滚动(TTM) · 近 10 年周频 · 20/50/80 分位 · 来源 蛋卷 · 更新于 xx」。不要把「危险值」三个字单独做成大标题。

**缓存 / 降级**：
- 进程内缓存 6h（估值一天一变；盘中不刷新也没问题）；`unavailable` 不缓存。
- 失败 → `200 + data_status: unavailable + error`，前端显示「暂无估值数据」，不要显示 0。
- 不并发打第三方（单请求串行 + 缓存），避免被限流。

**计算放哪**：分位数计算（quantile / percentile rank）放 `packages/core/src/number.ts` 或新建 `valuation.ts`，前端与 service 共用 —— 与现有 `computeRiskMetricsLocal` 的组织方式一致，也方便单测（钉死「同一序列 → 同一分位」）。

**pi 工具**：`get_index_valuation(index_code)`，参数与 HTTP 同源，`bun run gen:tools` 重新生成清单。

**工作量**

| 项 | 估算 |
|---|---|
| service provider（danjuan，含超时/降级/映射表） | 120–150 行 + 单测 80–120 行 |
| core 分位计算 | 40 行 + 单测 60 行 |
| route + DTO | 40–60 行 |
| 前端卡片（4 个 stat + 三档带值 + 小折线可选） | 150–220 行 + 组件测 60 行 |
| pi 工具 + gen:tools + 文档 | 60 行 |
| 合计 | **≈1.5–2 人日**（不含评审与口径讨论） |

**风险与监控**
- 第三方未公开接口 → 加 `logger.warn` 记录失败率；连续失败可在 `/api/health` 暴露（像 `eastmoney breaker` 那样）。
- 数据源改版 → 单测钉一份 **真实响应 fixture**（沿用 `tencent-a-share-quotes.test.ts` 的做法）。
- ToS：个人研究用途的公开接口，不做高频抓取（缓存 6h 已是天然限流）。

## 8. 不建议做的事

1. ❌ **给基金算「PE + 三档带值」**（尤其主动基金）。
2. ❌ **多源取平均**得到一个「综合 PE」——生成一个谁都不认的数字。
3. ❌ 把「危险值/机会值」做成买卖信号（红绿箭头、提醒买卖）。要做就做成中性的分位条。
4. ❌ 为了上证综指硬套「沪市平均 PE」而不标注口径（15.94 vs 上证综指加权 14.93，且历史分位完全不同）。
5. ❌ 现在就去接中证官方 xls 做「历史」——它只有 20 个交易日。

## 9. 推荐决策

| 阶段 | 做什么 | 理由 |
|---|---|---|
| **P1（建议）** | 指数详情页估值卡：PE + 10 年分位 + 20/50/80 分位值，窗口与口径显式展示，未覆盖指数老实显示「暂无」 | 成本最低、决策相关、失败可降级 |
| **P2（可选）** | pi 工具 `get_index_valuation`；把估值输入接进定投回测策略模板（如「分位 < 30% 加倍投」） | 与已有回测能力形成闭环 |
| **P3（不建议）** | 基金详情页 PE 五件套 | 覆盖 13%、口径误导、主动基金无效 |
| **替代** | 基金页只对指数基金显示「跟踪指数估值」，并明确标注「这是该指数的估值，不是基金的估值」 | 语义正确，成本比 P1 只多一个映射表 |

**一句话**：把「指数估值」做成一块诚实的、带口径说明的卡片值得做；把「基金的 PE 危险值」做出来只会得到一堆看起来专业、实际误导的数字。
