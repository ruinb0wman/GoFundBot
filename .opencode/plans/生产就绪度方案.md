## Phase 1 — 健康检查（P0）

> 提供 Scripts 自身健康端点和 Service 健康检查增强。

### 节点 1.1：Scripts `/health` 端点

| 步骤 | 文件 | 操作 |
|------|------|------|
| 1.1a | `Scripts/app.py` | 新增路由 `GET /health`，返回 JSON 格式健康信息 |
| 1.1b | 同上 | 检查项：① DB 连接（`SessionLocal().execute(text('SELECT 1'))`）② Service 连通性（`get_data_service_client().health()`）③ 启动时间戳 |

```python
# Scripts/app.py 新增，位置在 __main__ 之前
from sqlalchemy import text
from datetime import datetime, timezone

_START_TIME = datetime.now(timezone.utc)

@app.route('/health', methods=['GET'])
def health_check():
    checks = {}
    try:
        db = SessionLocal()
        db.execute(text('SELECT 1'))
        db.close()
        checks['database'] = 'ok'
    except Exception as e:
        checks['database'] = f'error: {e}'

    try:
        client = get_data_service_client()
        ds = client.health()
        checks['data_service'] = ds.get('status', 'unknown')
    except Exception as e:
        checks['data_service'] = f'error: {str(e)[:200]}'

    all_ok = all(v == 'ok' for k, v in checks.items() if k != 'uptime_seconds')
    return jsonify({
        'status': 'ok' if all_ok else 'degraded',
        'service': 'gofund-backend',
        'uptime_seconds': (datetime.now(timezone.utc) - _START_TIME).total_seconds(),
        'checks': checks,
    }), 200 if all_ok else 503
```

### 节点 1.2：Service 健康检查增强

| 文件 | 操作 |
|------|------|
| `Service/src/routes/health.routes.ts` | 增加缓存层健康状态、ProviderChain 连通性自检 |


## Phase 2 — 优雅关闭（P0）

> 确保 Scripts 和 Service 在收到 SIGTERM/SIGINT 后，能等待进行中的请求完成再退出。

### 节点 2.1：Scripts 优雅关闭

| 步骤 | 文件 | 操作 |
|------|------|------|
| 2.1a | `Scripts/app.py` `__main__` 块 | 用 `signal` + `atexit` 注册关闭钩子 |
| 2.1b | 同上 | 后台线程改为非 daemon，关闭时设置退出标志 |
| 2.1c | 同上 | `app.run()` 包在 try/finally 中，确保资源释放 |

```python
import signal
import atexit
import threading

_shutdown_flag = threading.Event()

def _graceful_shutdown():
    logger.info("收到关闭信号，开始优雅退出...")
    _shutdown_flag.set()
    timeout = 10
    deadline = time.time() + timeout
    for thread in threading.enumerate():
        if thread is not threading.main_thread() and thread.is_alive():
            remaining = deadline - time.time()
            if remaining > 0:
                thread.join(timeout=remaining)
    logger.info("优雅关闭完成")

atexit.register(_graceful_shutdown)
signal.signal(signal.SIGTERM, lambda s, f: sys.exit(0))
signal.signal(signal.SIGINT, lambda s, f: sys.exit(0))

if __name__ == '__main__':
    init_logging()
    # ... 现有初始化代码 ...
    try:
        app.run(debug=False, host='0.0.0.0', port=5000, threaded=True)
    finally:
        _graceful_shutdown()
```

### 节点 2.2：Service 优雅关闭

| 文件 | 操作 |
|------|------|
| `Service/src/index.ts` | 用 `process.on('SIGTERM')` + `server.close()` 实现优雅关闭 |

```typescript
import { createServer, type Server } from 'node:http';

const app = createApp();
const server: Server = createServer(app);

server.listen(port, () => { /* ... */ });

function gracefulShutdown(signal: string) {
  logger.info('收到关闭信号，开始优雅退出...', { signal });
  server.close(() => {
    logger.info('HTTP 服务已关闭');
    process.exit(0);
  });
  setTimeout(() => {
    logger.error('优雅关闭超时，强制退出');
    process.exit(1);
  }, 10_000);
}

process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
process.on('SIGINT', () => gracefulShutdown('SIGINT'));
```

### 节点 2.3：验收点

- [ ] `kill -TERM <pid>` 后日志输出 "收到关闭信号，开始优雅退出..."，服务在 10s 内退出
- [ ] 发送关闭信号时若有进行中的 HTTP 请求，请求正常完成（不被截断）
- [ ] `docker stop <container>` 等待时间 < 15s

## Phase 4 — API 版本化（P1，渐进式）

> 新端点使用 `/api/v1/` 前缀，旧端点保留兼容（遗留路径不做破坏性变更）。

### 节点 4.1：Blueprint 重组

| 步骤 | 文件 | 操作 |
|------|------|------|
| 4.1a | `Scripts/app.py` | 新路由全部挂载在 `/api/v1/` 下 |
| 4.1b | 新建 `Scripts/routes_v1/` 目录 | 按领域拆分 blueprint（fund/watched/market/screening 等） |
| 4.1c | `Scripts/app.py` | 旧路由标记 `# @deprecated`，保留功能性但记录 deprecated 日志 |

**策略**：
```
现有路由 (不改)         → /api/fund/<code>         (保留，内部重定向到 v1)
新路由                 → /api/v1/fund/<code>
Service 代理保留   → /api/data-service/...     (不版本化，内部用)
```

### 节点 4.2：迁移垫片

| 文件 | 操作 |
|------|------|
| `Scripts/core/version_shim.py`（新建） | 提供 `@deprecated_route` 装饰器，旧路由自动返回 `Warning: Deprecated` 头 |
| `Scripts/app.py` | 旧路由包裹在 `deprecated_route` 中 |

### 节点 4.3：验收点

- [ ] `curl -I localhost:5000/api/fund/000001` 返回 `X-Deprecated: true` 头（旧路由）
- [ ] `curl localhost:5000/api/v1/fund/000001` 返回与旧路由相同数据 + 无 deprecated 头
- [ ] Frontend 在开发模式下收到 `X-Deprecated` 头时 console.warn 提示升级

### 节点 5.2：核心端点文档化（优先批次）

| 端点组 | 端点数量 | 优先级 | 说明 |
|--------|----------|--------|------|
| 基金查询 | 8 条 (`/api/v1/fund/*`) | P0 | 搜索、详情、分析、趋势、对比等 |
| 自选管理 | 10 条 (`/api/v1/watchlist/*`) | P0 | CRUD + 分组 + 估算刷新 |

| 其他 | ~25 条 | P2 | 回测、研究、数据统计等 |

各端点 `@swag_from` 装饰器示例：

```python

@swag_from({
    'tags': ['Fund'],
    'summary': '获取基金完整详情',

        {'name': 'fund_code', 'in': 'path', 'type': 'string', 'required': True, 'description': '基金代码'},
        {'name': 'source', 'in': 'query', 'type': 'string', 'enum': ['auto', 'legacy', 'data_service'], 'default': 'auto'},
    ],
    'responses': {
        200: {'description': '基金详情'},
        404: {'description': '基金未找到'},
    }
})
def get_fund_detail(fund_code): ...
```

## 依赖关系

```
Phase 0 ──→ Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4 ──→ Phase 5
(日志补完)   (健康检查)   (优雅关闭)   (metrics)    (版本化)    (文档)

Phase 0 必须先完成（日志是健康检查和优雅关闭的观测基础）。
Phase 1 可独立启动（不依赖 print→logger 迁移）。
Phase 2 依赖 Phase 0（需要 logger 输出关闭日志）。
Phase 3-5 可并行于前序 Phase 启动，无强依赖。
```

## 中断恢复指南

1. 每完成一个**节点**（非整个 Phase），在下方状态表打勾
2. 恢复时从第一个未打勾的节点继续
3. 每个节点独立可验证：节点验收点完成后即可标记 ✅
4. Phase 验收点在 Phase 内全部节点完成后统一验证
